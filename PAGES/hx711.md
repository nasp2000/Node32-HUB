# HX711 Weight Sensor — `/hx711`

> One-stop reference for the **HX711 load-cell / weight-sensor page**: purpose, layout, every button/input, client logic, API endpoints, persistence and the firmware-side HX711 driver engine. Written for both humans and AI agents.

---

## 1. Objective

Configure and operate the **HX711 24-bit load-cell ADC**: view the live weight reading, trigger an immediate measurement, tare (zero) the scale, and persist calibration (gain, samples, scale factor, tare offset, display unit), read interval and monitor-output options. All settings persist to LittleFS and apply without reboot, except **gain** (see HX-4).

## 4. Inputs

| Input | ID | Type / range | Notes |
|---|---|---|---|
| Enable sensor | `sensorEnabled` | checkbox | gates auto-read (`shouldAutoRead`) and `performReading` |
| Read interval | `readInterval` | select 2/5/10/30/60/300/600 s | default 60; server stores any int, no clamping |
| Amplifier gain | `gain` | select 128/64/32 | channel A-128 recommended; needs reboot to take effect (see HX-4) |
| Samples | `samples` | number 1–64, default 8 | UI hint: "More samples = more stability, but slower."; struct comment says 1–20 |
| Scale factor | `scaleFactor` | number step 0.001, default 1.0 | `(raw − tare) / scale_factor = weight`; hint: "E.g.: 441.0 for grams…" |
| Tare offset | `tareOffset` | number step 1, default 0 | auto-updated after tare; editable manually |
| Weight unit | `weightUnitSel` | select 0–4 (g/kg/lbs/oz/N) | display only; conversion factor is the user's `scale_factor` |
| Monitor data | `injectBuffer` | checkbox | injects each reading into the RX/monitor buffer |
| CSV output | `outputCsv` | checkbox | `HX711,weight,<v>,<unit>` vs human-readable `"⚖️ Peso: …"` |

## 6. Client-side logic (inline JS in `page_hx711_asset.h`)

- **`t(key, fallback)`** (`:152-155`) — `window._t` wrapper with English fallback.
- **`uiLocale()`** (`:157-160`) — `localStorage ui_lang_code` or `document.lang` → `en-GB` / `pt-PT` for timestamp formatting.
- **`updateDisplay(d)`** (`:162-182`) — maps `weight_unit` 0–4 via `UNIT_LABELS`, prints `last_weight.toFixed(3)`, formats `last_reading_time` (unix s) or falls back to `"No reading"`.
- **`loadConfig()`** (`:184-208`) — `GET /api/hx711-config` (`cache:no-store`), fills all inputs, calls `updateDisplay`; if never read, auto-triggers `measureNow()` after 600 ms.
- **`saveConfig()`** (`:210-242`) — `disableBtn` + `showLoading()`, JSON body of all 9 fields, checks HTTP status then `d.ok`; `finally` → `hideLoading()` + `enableBtn`.
- **`measureNow()`** (`:244-255`) — status `"🔬 Measuring..."` → `POST /api/hx711-measure` → `updateDisplay` + `"✅ Reading complete!"`.
- **`performTare()`** (`:257-280`) — confirm dialog, then `POST /api/hx711-tare`; on `d.tare_offset` updates the offset field + display + `"✅ Tare applied!"`. No fallback if `customConfirm` is missing (see HX-3).
- **`showStatus(msg, type)`** (`:282-292`) — prefers `customAlert`; hidden `#status` div is the fallback (green/red/blue border per type, auto-hide 3 s).
- Listeners bound at `:294-296`; boot via `setTimeout(loadConfig, 150)` (`:298`). No arrow functions — project rule honoured.

## 7. Server API

Handlers in `chatgpt/src/webpages/handlers_unified/sensor_handler.cpp:454-485` (declared in `sensor_handler.h:38-43`).

### `GET /api/hx711-config` (`:456-459`)

Returns `hx711ConfigManager.toJson()` (`sensor_hx711_config.cpp:112-133`):

```json
{
  "sensor_enabled": true, "data_pin": 19, "clk_pin": 20, "gain": 128,
  "samples": 8, "read_interval_sec": 60, "scale_factor": 1.0,
  "tare_offset": 0, "weight_unit": 0, "inject_to_buffer": false,
  "output_csv": true, "alert_min": 0.0, "alert_max": 0.0,
  "last_weight": 0.0, "last_raw": 0, "last_reading_time": 0
}
```

### `POST /api/hx711-config` (`:461-468`)

`updateFromJson(req.body)` → `{"ok":true}`, or HTTP 400 `{"ok":false,"msg":"Erro ao guardar config HX711"}` (message is PT). Applies `scale_factor` + `tare_offset` to the live driver, then saves (gain is stored but **not** applied live — see HX-4).

### `POST /api/hx711-measure` (`:470-474`)

`performReading()` (returns false when disabled/uninitialised, still HTTP 200) → full `toJson()` snapshot.

### `POST /api/hx711-tare` (`:476-484`)

`performTare()` → full `toJson()` (with new `tare_offset`), or HTTP 500 `{"ok":false,"msg":"Falha na leitura de tara"}` (message is PT).

## 8. Persistence

`HX711ConfigManager::begin("/config/sensor_hx711.json")` (`sensor_hx711_config.h:79`, default path) via `SensorConfigBase`: loads on boot (`initFilesystem`, `sensor_config_base.h:29-50`), atomic save (`.tmp` → bytes>0 → remove → rename, `:101-111`). Saved on every config POST (`sensor_hx711_config.cpp:159`), every tare (`:77`), and every 8 h (`PERSIST_INTERVAL_MS`, `sensor_config_base.h:26`, driven by `loop_blocks.h:26`). `ConfigManager` only reserves the slot — `addPage("sensor_hx711", 4096)` is explicitly "managed independently outside ConfigManager" (`ConfigManager.cpp:921-924`).

## 9. Runtime engine

- **Driver** `HX711Sensor` (`chatgpt/src/sensors/sensor_hx711.h:63-123`, `sensor_hx711.cpp`): 2-wire bit-bang (DOUT + PD_SCK), 24-bit sign-extended reads (`:79-110`), `readAverageRaw` (`:134-141`), `readWeight(samples) = (raw − tare) / scale` with `scale==0` guard (`:147-154`), `tare()` (`:160-164`), power down/up (`:170-182`). Pins default GPIO5/4 (`sensor_hx711.h:33-38`), overridden to **GPIO19/20** by `board_pins.h:107-108` — mutually exclusive with MAX31865 and native USB.
- **Manager** `HX711ConfigManager` (`sensor_hx711_config.cpp`): `begin()` starts the driver with stored pins/gain and restores scale/tare (`:22-43`); `performReading()` caches `last_weight`/`last_raw`/timestamp and optionally injects to the monitor buffer (`:49-67`, `:96-106`); `performTare()` re-zeros and saves (`:73-80`).
- **Scheduling**: `loop_blocks.h:22-27` auto-reads when `shouldAutoRead()` (interval elapsed, `sensor_config_base.h:57-61`); manager boot from `sensor_config.cpp:135-138` (include via `chatgpt.ino:144-146`).
- **Home link**: gated Sensors button at `home_page_renderer.h:191-193`.
