# MAX31865 RTD — `/max31865`

> One-stop reference for the **MAX31865 RTD temperature sensor page** (PT100/PT1000): purpose, layout, every button/input, client logic, API endpoints, persistence and the firmware-side RTD-to-digital engine. Written for both humans and AI agents.

---

## 1. Objective

Configure and read a **MAX31865 RTD-to-digital converter** (PT100 or PT1000 probe, 2/3/4-wire) over SPI: live temperature with fault badge, enable + auto-read interval, probe type, wiring, display unit, calibration offset, and monitor/CSV output options. Settings persist to LittleFS and the driver auto-reads in the main loop without reboot.

## 4. Inputs

| Input | ID | Type / range | Notes |
|---|---|---|---|
| Enable sensor | `sensorEnabled` | checkbox | maps to `sensor_enabled`; gates auto-read and manual reads |
| Reading interval | `readInterval` | select 2/5/10/30/60/300/600 s | maps to `read_interval_sec`; drives `shouldAutoRead()` |
| Probe type | `rtdType` | select 0=PT100 / 1=PT1000 | maps to `rtd_type`; selects Rref/R0 pair |
| Wiring | `wiring` | select 0=2-wire / 1=3-wire / 2=4-wire | maps to `wiring`; value `2` has no distinct driver effect (see §11.2) |
| Temperature unit | `tempUnitSel` | select 0=°C / 1=°F / 2=K | maps to `temp_unit`; display-only, offset applied first |
| Calibration offset | `calibrationOffset` | number, step 0.01 (°C) | maps to `calibration_offset`; added to °C reading before unit conversion |
| Data in Monitor | `injectBuffer` | checkbox | maps to `inject_to_buffer`; pushes each reading to the RX/monitor buffer |
| CSV output | `outputCsv` | checkbox | maps to `output_csv`; switches monitor line to `MAX31865,temp,<v>,<unit>` |

SPI pins (`cs_pin`, `mosi_pin`, `miso_pin`, `clk_pin`) are part of the JSON API but have **no UI inputs** (see §11.5).

## 6. Client-side logic (inline JS in `page_max31865_asset.h:152-291`)

- **`t(key, fallback)`** (`:153-156`) — `window._t` wrapper with English fallback; **`uiLocale()`** (`:158-161`) — `en-GB`/`pt-PT` for timestamp formatting.
- **`updateDisplay(d)`** (`:163-202`) — `last_temp` → 2 decimals (amber when `last_fault` set, else green; `--` when null); `last_unit` string straight into the label; fault badge `⚠ FAULT: 0x<HEX>` + `.fault` class vs `✓ OK`; `last_reading_time` (epoch s) → locale date/time, else `No reading`.
- **`loadConfig()`** (`:204-227`) — `GET /api/max31865-config` (`cache:'no-store'`), fills all 8 inputs, calls `updateDisplay`; if no reading yet, auto-fires `measureNow()` after 600 ms (`:221-223`).
- **`saveConfig()`** (`:229-260`) — builds JSON body from the 8 inputs, `POST /api/max31865-config`; checks **`d.ok`** (not `d.success` — see §11.3); `disableBtn(btnSave)` + `showLoading()` / `hideLoading()` + `enableBtn(btnSave)`.
- **`measureNow()`** (`:262-273`) — status `🔬 Measuring...`, `POST /api/max31865-measure`, refresh display, status `✔️ Reading complete!`.
- **`showStatus()`** (`:275-285`) — prefers `customAlert`; `#status` div is a fallback only. No arrow functions — project rule honoured.

## 7. Server API

Handlers in `chatgpt/src/webpages/handlers_unified/sensor_handler.cpp:511-531` (decl. `sensor_handler.h:51-55`), all `#if ENABLE_MAX31865==1`.

### `GET /api/max31865-config` (`:512-515`)

Returns `max31865ConfigManager.toJson()` (`sensor_max31865_config.cpp:111-138`):

```json
{
  "sensor_enabled": true, "cs_pin": 5, "mosi_pin": 23, "miso_pin": 19, "clk_pin": 18,
  "rtd_type": 0, "wiring": 0, "temp_unit": 0, "calibration_offset": 0.0,
  "read_interval_sec": 10, "inject_to_buffer": false, "output_csv": true,
  "alert_low": -999.0, "alert_high": 999.0,
  "last_temp": 23.46, "last_unit": "°C", "last_fault": 0, "last_reading_time": 1757345200
}
```

`last_temp` is `null` before the first reading; `alert_low/high` are stored but have no UI.

### `POST /api/max31865-config` (`:517-524`)

`updateFromJson(req.body)` (`sensor_max31865_config.cpp:140-160`) applies any present keys (pins, `rtd_type`, `wiring`, `temp_unit`, `calibration_offset`, `read_interval_sec`, flags, alerts) then saves. No range validation (see §11.4). Responses: `200 {"ok":true}` or `400 {"ok":false,"msg":"Erro ao guardar config MAX31865"}` (Portuguese literal — see §11.6).

### `POST /api/max31865-measure` (`:526-530`)

`performReading()` then returns the same `toJson()` snapshot above.

## 8. Persistence

Standalone sensor file **`/config/sensor_max31865.json`** (default in `sensor_max31865_config.h:81`), managed by the `SensorConfigBase` template (`sensor_config_base.h`):

- Atomic write: `.tmp` → bytes>0 check → remove original → rename (`:101-111`).
- Load on `begin()` via `initFilesystem()`; defaults from the `MAX31865Config` constructor (`sensor_max31865_config.h:54-73`).
- Every successful POST saves immediately (`updateFromJson` → `saveToFile()`, `sensor_max31865_config.cpp:159`); plus `periodicPersist()` every 8 h (`PERSIST_INTERVAL_MS`, `sensor_config_base.h:26,65-72`), driven from `loop_blocks.h:47`.
- Also registered as a `ConfigManager` page slot `sensor_max31865` (4 KB) (`ConfigManager.cpp:927,2026`) and in the self-test config list (`selftest_handler.cpp:33`).

## 9. Runtime engine

Two layers, both `#if ENABLE_MAX31865==1`:

- **Driver `MAX31865Sensor`** (`sensors/sensor_max31865.h`, `sensor_max31865.cpp`): no external library, SPI 4 MHz MODE1. `begin()` (`:30-64`) writes config `0x80` (VBIAS on, one-shot mode), sets the 3-wire bit only for `MAX31865_3WIRE`, and verifies via readback. `readTemperature()` (`:70-95`) triggers one-shot (bit 5), `delay(70)`, reads the 15-bit code; fault bit → read fault reg, `clearFault()`, return NAN. `rawToTemperature()` (`:114-144`) is Callendar-Van Dusen (`A=3.9083e-3`, `B=-5.775e-7`, Rref 430 Ω / 4300 Ω) with one Newton-Raphson iteration below 0 °C. Fault register `0x07` via `readFaultStatus()`/`clearFault()` (`:150-159`).
- **Manager `MAX31865ConfigManager`** (`sensor_max31865_config.cpp`): `begin()` (`:22-41`) does `SPI.begin(clk, miso, mosi)` and `sensor.begin(cs, type, wiring)` only when enabled. `performReading()` (`:47-69`) caches raw °C, fault byte, display value (`calibration_offset` added **before** `toDisplayUnit()`), and epoch timestamp; injects `🌡️ RTD: <v> <unit>` or `MAX31865,temp,<v>,<unit>` into the RX/monitor buffer when enabled (`:95-105`).
- **Loop**: `loop_blocks.h:43-48` — `shouldAutoRead()` (interval elapsed, `:57-61` of base) → `performReading()` → `periodicPersist()`. Included from `chatgpt.ino:153-155`.
