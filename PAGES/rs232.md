# RS232 — `/rs232`

> Reference for the **RS232 / DB09 configuration page**: serial parameters, templates
> (max 6), advanced electrical options and sniffer-mode behavior. Written for both humans
> and AI agents.

---

## 1. Objective

Configure the physical **RS232 serial port** (enable, baud/data/parity/stop, RX-TX pin
inversion, read timeout, XON/XOFF) and manage **connection templates** that the Scheduled
Commands page (`/commands`) can apply later without reconfiguration. Shows live port status.

## 4. Inputs

| Input | ID / name | Notes |
|---|---|---|
| Enable RS232 | `rs232_enabled` | checkbox; JS appends hidden `true/false` because unchecked checkboxes don't serialize; hidden entirely in sniffer mode |

| Parity | `parity` | none / even / odd |
| Stop bits | `stop_bits` | 1 / 2 |
| Invert pins | `invert_pins` | hidden `false` appended when unchecked |
| Read timeout | `read_timeout` | min 100 / max 10000 client-side only |
| XON/XOFF | `use_xon_xoff` | software flow control |
| Template name | `template_name` | free text; required by save handler |

## 6. Client-side logic

Inline `<script>` (auto.js supplies `customAlert`/`customConfirm`/`showSavedCard`):

- `rt(k, fb)` — i18n helper (`window._t` → `localStorage.ui_lang_cache` → fallback).
- `applyRs232Texts()` — localizes status label, three rich info boxes (`innerHTML`),
  template notes and placeholder.
- `loadCurrentConfig()` — `GET /api/config?section=rs232&t=<ts>` (no-cache):
  - `window._snifferMode = !!d.sniffer_mode` → hides the enable-checkbox row;
  - `window._rs232_baudlist` from `rs232.baudrate_list` (fallback default list);
    select value set via `baudrate_index`;
  - fills all fields; retries after 2 s on network failure;
  - ends with `updateRS232Status()`.
- `updateRS232Status()` — `Active ({baud} bps)` / `Disabled` / `🔍 Sniffer active`.
- `loadRs232Templates()` — `GET /api/rs232-templates` → renders cards
  (`{name} {baud}-{data}-{parity}-{stop}` [+ `-Invert`]) with per-card delete checkbox.
- Form submit — adds hidden `baudrate_index`, forced `rs232_enabled`, optional
  `invert_pins=false`; posts; on success alerts + `showSavedCard()` + reload.
- Tab setup IIFE — finds sections by inline style selector
  `div[style*='border:2px solid #3b82f6']` containing an `h2`; labels hardcoded
  `['Config','Avancado']`.

## 7. Server API

| Endpoint | Method | Handler | Purpose / shape |
|---|---|---|---|
| `/api/config?section=rs232` | GET | `config_handler.cpp:143` | `{rs232:{enabled,baudrate_index,data_bits,parity,stop_bits,invert_pins,read_timeout_ms,use_xon_xoff,baudrate_list:[…]}}` + top-level `sniffer_mode` bool |
| `/api/config` | POST | `config_handler.cpp:206` | accepts the fields above; `read_timeout_ms` accepted as any int (**no clamp server-side**) |
| `/api/rs232-templates` | GET/POST/DELETE | `handlers/rs232_template_handler.cpp:268,272,420,445` (registered at `web_routes_config.cpp:71`, gate `ENABLE_RS232`) | list/save/delete named templates; **max 6**, oldest overwritten (`ConfigManager.h:1438 addOrUpdateRs232Template`) |
| `/api/rs232/persist-current-template` | POST | registered `web_routes_config.cpp:69` | persists current runtime params as a template (used elsewhere) |
| `/api/rs232-status` | GET | `web_routes_config.cpp:66` (`handleRs232StatusGet`, gate `ENABLE_RS232`) | live driver state |
| `/api/test-rs232` | POST | `web_routes_config.cpp:67` (`handleTestRs232Post`) | sends a test frame out the port |

Template save payload mirrors all form fields so a template can be re-applied verbatim
from `/commands` (Scheduled Commands apply step calls `applyRS232Config`,
`rs232_config_impl.h:23`).

## 9. Runtime engine

- Saving triggers re-init of the UART with new parameters (driver task restarts).
- **Sniffer mode** (compile-time `ENABLE_SNIFFER`): passive capture replaces normal
  two-way operation; page hides the enable checkbox and status shows `🔍 Sniffer active`.
- Templates are consumed by Scheduled Commands: applying one writes its stored params
  through the same config path (`applyRS232Config`).

## 11. Review findings & improvement ideas

| # | Finding | Pri | Suggestion |
|---|---|---|---|
| 1 | WiFi route not feature-gated (`server.on("/rs232")` compiled regardless of `ENABLE_RS232/SNIFFER`) while the Ethernet mirror is gated; route also sends `Content-Language: pt` although the document is `lang='en'`. | Medium | Gate like Ethernet side; drop or fix the header. |
| 2 | Widespread arrow functions + `async/await` (`.then(r=>r.json())`, `.map(x=>x.toString())`, `async function()` in save-template) — violates the no-arrow-function rule. | Low | Rewrite with `function(){}`. |
| 3 | Tab labels hardcoded PT: `['Config','Avancado']` (also misspelled — missing ç). | Low | Route through i18n keys. |
| 4 | Delete flow fires N parallel `DELETE`s without awaiting between; every response re-renders the list and pops its own `✅ Template deleted!` alert (stacked dialogs). | Low | Sequential loop with single summary alert afterwards. |
| 5 | `read_timeout`: client enforces 100–10000 ms, server stores any int (`toInt()`) — mismatch allows invalid values via direct API use. | Low | Clamp server-side. |
| 6 | `rs232StatusSniffer` i18n key missing from both language packs — sniffer users always see English regardless of UI language. | Low | Add key to EN+PT. |
| 7 | Baud stored as index into server-provided `baudrate_list`; if the server list order ever changes, saved indexes silently point at different rates. | Info | Store the numeric baud value instead of index. |
| 8 | Template cards inject raw names into innerHTML (`'<div class="tpl-name">'+t.name+'</div>'`) — a template name containing markup breaks layout / self-XSS. | Low | Build nodes with `textContent`. |
