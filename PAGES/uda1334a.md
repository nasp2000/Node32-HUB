# UDA1334A audio DAC — `/uda1334a`

> One-stop reference for the **UDA1334A DAC config page**: purpose, layout,
> every button/input, client logic, API endpoints, persistence and the
> firmware-side I2S/DAC engine. Written for both humans and AI agents.

---

## 1. Objective

Configure the **UDA1334A I2S DAC board** (sound output for the radio pack): sample rate, bit depth and automatic routing, show live DAC state, and play a test melody. Changes apply **without reboot** (I2S clock reconfigured at request time).

## 6. Client-side logic (inline JS in `page_audio_dac_uda1334a_asset.cpp:81-162`)

- **`wt(k, fb)`** (`:82`) — `window._t(k, fb)` if present, else `ui_lang_cache` from localStorage, else fallback. No arrow functions — project rule honoured.
- **`loadUDAConfig()`** (`:94`, on window load) — `GET /api/uda1334a-config` (`cache:'no-store'`); fills `uda-sr` (default `44100`), `uda-bd` (default `16`), `uda-auto-routing`, and the four status spans (`initialized`/`enabled` via `wt('opYes'/'opNo')`). Failure → `customAlert('❌ ' + wt('uda1334aLoadError', …))`.
- **Save handler** (`:112`) — `FormData` → JSON (`parseInt` for rate/depth, `=== 'on'` for routing) → POST with `Content-Type: application/json`; success uses `wt('alertSaved', …)`, failure prefixes `wt('emailErrorPrefix', …)` plus `uda1334aSaveFailDefault`; network error → `uda1334aSaveError`.
- **Test handler** (`:144`) — bare `POST /api/uda1334a-test`; success → `wt('uda1334aTestRunning', …)`, failure → `emailErrorPrefix` + `uda1334aTestFailDefault`, network error → `uda1334aTestError`.
- Nothing on the page ever calls `/api/uda1334a-timing` (see UDA-2).

## 7. Server API

Handlers in `chatgpt/src/webpages/handlers_unified/audio_handler.cpp` (declarations `audio_handler.h:7-10`).

### `GET /api/uda1334a-config` (`:122`)

Returns `uda1334aConfig.toJson()` (`audio_dac_uda1334a_config.cpp:150`):

```json
{"enabled":true,"sampleRate":44100,"bitDepth":16,"autoRoutingEnabled":false,"initialized":false}
```

`initialized` = `udaDac.isInitialized()` (runtime only, not persisted).

### `POST /api/uda1334a-config` (`:127`)

JSON body `{sampleRate, bitDepth, autoRoutingEnabled}`. Invalid JSON → 400 `{"success":false,"message":"Invalid JSON"}`; save failure → 500 `Failed to save config`; otherwise applies to hardware via `_applyUda1334aRuntimeConfig()` (`:40` — `begin()` if uninitialised, else `setAudioFormat()`) → 200 `{"success":true,"message":"Config saved"}` or 500 `Failed to initialize DAC` / `Failed to apply DAC format`. **No value whitelist** (see UDA-1).

### `POST /api/uda1334a-test` (`:152`)

Spawns `udaTestSoundTask` (`playTestSound()` in its own FreeRTOS task, 4 KB stack) and immediately returns 200 `{"success":true,"message":"Test sound playing"}`. Never blocks the HTTP task.

### `POST /api/uda1334a-timing` (`:178`)

Optional JSON `{seconds}`; accepted only when `10 <= seconds <= 300`, else default `60`. Stops radio first (`radioAudioStopDeferred`, waits ≤3 s), spawns `udaTimingTask` → `playTimingTest(seconds)`, returns 200 `{"success":true,"message":"Timing test (<n>s) started"}`. Result is reported on Serial/Web Monitor, not HTTP. **No UI calls it** (see UDA-2).

## 8. Persistence

Dedicated manager, **not** `ConfigManager`: `UDA1334AConfigManager uda1334aConfig` (`audio_dac_uda1334a_config.cpp:11`) → **`/config/uda1334a.json`** (`audio_dac_uda1334a_config.h:11`):

```json
{"enabled":true,"sampleRate":44100,"bitDepth":16,"autoRoutingEnabled":false}
```

- Atomic write: `.tmp` → `bytes > 0` check → remove original → rename (`audio_dac_uda1334a_config.cpp:82-106`).
- Defaults when missing: `enabled=true, 44100 Hz, 16-bit, autoRouting=false` (`:113-120`); loaded at boot via `uda1334aConfig.begin()` (`setup_impl.h:283`).
- `enabled` is forced `true` on load (`:65`) and ignored in `updateFromJson()` (`:163-166`): "no disable option" — the status line therefore always reads Yes (see UDA-3).

## 9. Runtime engine (I2S DAC driver + radio output)

- **`UDA1334ADAC udaDac`** (`chatgpt/src/audio_dac_uda1334a.h:108`, impl `.cpp:12`): `begin(fmt)` installs the I2S TX driver (`:25-83`); `setAudioFormat()` re-clocks a live stream (`:85-105`); `write()` blocking `i2s_write` (`:107-118`); `end()` uninstalls (`:120-128`); `playTestSound()` ascending-melody self-test (`:136-191`); `playTimingTest(seconds)` clock-accuracy probe reporting via `sendVirtualMessage` (`:193-287`); `setMuted()` via optional MUTE pin (`:130-134`).
- **Pins/defaults** (`.h:15-47`): BCLK GPIO26, LRCK GPIO25, DOUT GPIO27, MCLK −1 (disabled), MUTE −1 (disabled), port `I2S_NUM_0`, DMA 4×256. Overridable in `board_pins.h`/`user_config.h`.
- **Boot**: DAC driver install is deferred to `radioAudioRuntimeLoop()` — `i2s_driver_install()` DMA in PSRAM corrupts FatFS if run before SD access (`setup_impl.h:285-287`). First playback self-heals via `radioAudioEnsureOutput()` (`radio_audio_runtime.cpp:1105-1117`), which builds `AudioFormat` from the persisted sampleRate/bitDepth (`:1111-1112`).
- **POST apply path**: `handleUda1334aConfigPost` → `_applyUda1334aRuntimeConfig` (`audio_handler.cpp:40-60`) → `begin()` or `setAudioFormat()` — takes effect immediately.

## 11. Review findings & improvement ideas

| # | Finding | Severity | Suggested fix |
|---|---|---|---|
| UDA-1 | **No server-side value validation.** `handleUda1334aConfigPost` (`audio_handler.cpp:127`) forwards any JSON numbers to `updateFromJson()` (`audio_dac_uda1334a_config.cpp:163`), which accepts any `sampleRate`/`bitDepth` and applies them to `i2s_set_clk`. The UI (2 rates × 2 depths) is also narrower than the documented hardware range (16–192 kHz, 16/24/32-bit per `audio_dac_uda1334a.h:11,52-53` and `audio_dac_uda1334a_config.h:20-21`). | Medium | Whitelist `{44100,48000[,96000,192000]}` × `{16,24[,32]}` in `updateFromJson()` and return 400 otherwise; then align UI options with the whitelist. |
| UDA-2 | **Timing endpoint has no UI.** `POST /api/uda1334a-timing` is registered (`web_routes_audio.cpp:135`) but no page JS calls it (`page_audio_dac_uda1334a_asset.cpp:81-162` only fetches `-config` and `-test`); its keys `uda1334aTimingBtn`/`uda1334aTimingRunning` (`lang_en_ui.h:469-470`) are unused. | Low | Add a "🕐 60s Test" button posting to `/api/uda1334a-timing` (result goes to the Serial Monitor), or remove the endpoint from the registry/API reference. |
| UDA-3 | **"Enabled" status is a dead display.** `#enabled-status` (`page_audio_dac_uda1334a_asset.cpp:24`) always renders Yes: `load()` forces `_config.enabled = true` (`audio_dac_uda1334a_config.cpp:65`), `updateFromJson()` ignores `"enabled"` (`:163-166`), and the prod UI has no enable control (the web test fixture still has `#uda-enabled`, `tests/web/pages/audio_dac_uda1334a_asset.html:37`). | Low | Remove the status line, or re-introduce the enable checkbox (fixture + `uda1334aEnableDac`/`udaTipEnable` keys already exist). |
| UDA-4 | **Card titles reuse other pages' keys.** Status header uses `rs232StatusTitle` and config header uses `ethernetConfigTitle` (`page_audio_dac_uda1334a_asset.cpp:19,29`). Renaming those keys for RS232/Ethernet silently retitles this page. | Low | Add dedicated `udaStatusTitle` / `udaConfigTitle` keys and use them here. |
| UDA-5 | **Second info block binds as plain text.** The lower info div uses `data-i18n='uda1334aInfo'` (`page_audio_dac_uda1334a_asset.cpp:68`) while the upper banner correctly uses `data-i18n-html` (`:30`); the same key is also bound twice on one page, so one overwrites the other depending on translator order. | Info | Use `data-i18n-html` on both blocks (or a separate key for the long paragraph). |
