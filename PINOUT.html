⚙ PACK_S3_CNC — GcodeSender (UART default, USB Host OTG selector)

Enables: GRBL, USB_HOST, SDCARD, ASYNC_WEBSOCKET. Disables: RS232, DB25, MODBUS, CAN, sensores, TELNET, OLED.

GRBL transport selectable at runtime (session-only): default UART (Serial2 GPIO16/17 via FTDI/CH340 3.3V) — native USB port stays free for Serial Monitor; switch to USB Host OTG (GPIO19/20, CH340/CP2102 GRBL controller) in the GRBL page selector. USB Host always runs; choice is not persisted (reverts to UART on reboot).

GPIOFunctionNotes
16/17GRBL UART TX/RX (default)FT232RL ou CH340G (3.3V!) ligado ao GRBL controller
19/20USB D-/D+ (OTG)Adaptador OTG → CH340/CP2102 do GRBL controller (após seletor OTG)

⚠ GPIO16/17: These are OPI PSRAM pins on N16R8 — they work for GRBL UART in practice, but DO NOT connect MAX3232 (±12V glitch on boot).
With OTG transport, native USB port is taken by USB Host; debug via UART0 (GPIO43/44) with USB-UART adapter. packs/pack_s3_cnc_usb.h

Subsystem wiring — N16R8

RS232 — UART2, option A: MAX3232 (3.3 V, original)

SignalGPIONotes
TX17RS232_DEFAULT_TX_PIN. Connect to MAX3232 T1IN.
RX16RS232_DEFAULT_RX_PIN. Connect to MAX3232 R1OUT.
TX idle = ±5.5 V. Older equipment (e.g. RAMBOX) may not respond without DSR asserted.

RS232 — UART2, option B: SZFYD module with RTS (RAMBOX / DTR-dependent devices)

SignalGPIONotes
TX17RS232_DEFAULT_TX_PIN → module TxIN.
RX16RS232_DEFAULT_RX_PIN ← module RxOUT.
RTS18UNIKON_RTS_PIN → module RTS TTL. Define UNIKON_RTS_PIN 18 in user_config.h.
VCC—3.3 V
DB9 connector (Node32 side) — jumper together: pin 7 (RTS) + pin 6 (DSR) + pin 1 (DCD) + pin 8 (CTS).
Cable to RAMBOX: straight (direct) — pin 2→2, pin 3→3, pin 5→5.
GPIO18 driven HIGH by unikonBegin() → module RTS → DB9 pin 7 → RS232 negative voltage → RAMBOX sees DSR+DCD+CTS asserted → responds to poll frames.

Serial Sniffer — Passive dual-channel RS232 monitor

The sniffer listens passively to two RS232 lines simultaneously without interrupting the communication. Useful to monitor traffic between a PC and a serial device (printer, PLC, legacy equipment) without altering the original circuit.

Enable with #define ENABLE_SNIFFER 1 in user_config.h. When active, ENABLE_RS232 and ENABLE_DB25 are automatically forced to 0 (UART pin conflict).

Exclusive mode: the sniffer occupies UART1 and UART2. It cannot coexist with RS232, DB25/Arduino Bridge, or Modbus RTU in the same build. Plan feature flags before flashing.
Banned GPIO ranges on ESP32-S3 N16R8 (OPI PSRAM / OPI Flash):
• GPIO16–17: OPI PSRAM interface — driven by the bootloader at power-on. Connecting a MAX3232 R1OUT here injects a brief −12 V glitch onto the RS232 bus at every boot, breaking the monitored communication.
• GPIO33–37: OPI PSRAM data bus — continuously driven by the PSRAM controller. The UART hardware cannot use these pins; no data is ever received on them.
• GPIO26–32: OPI Flash bus — same reason.
• GPIO19–20: USB D+/D−.
• GPIO43–44: UART0 Serial debug.
Use GPIO4 and GPIO5 for the sniffer (confirmed safe on N16R8 devkit).

How it works

Two independent UART receivers run in RX-only mode (TX pin = −1). Each UART reads bytes from a MAX3232 transceiver wired to one direction of the RS232 bus:

  • Channel 1 (S1) — monitors the PC→Device direction (DB9 pin 3 = PC TXD).
  • Channel 2 (S2) — monitors the Device→PC direction (DB9 pin 2 = Device TXD).

Bytes accumulate in PSRAM buffers (128 KB each). When a CR or LF terminator is detected, the completed line is injected into the firmware’s global message pipeline prefixed with [S1] or [S2], and is visible in the Serial monitor, Telnet console, and the /api/monitor web endpoint.

RX-only wiring rule: connect only the R1OUT (TTL header pin labelled RXD) of each MAX3232 to the ESP32 GPIO. Never connect RS232 bus lines (±12 V) directly to the ESP32 — the pin would be damaged instantly.

MAX3232 module female DB9 — critical wiring note

Blue MAX3232 breakout modules with integrated female DB9 connectors are typically wired in DCE configuration:

Female DB9 pinInternal connection (DCE)Action
2T1OUT — active RS232 outputDo NOT connect to bus. Driving T1OUT onto the RS232 line fights the real transmitter and breaks communication.
3R1IN — passive RS232 inputConnect bus signal here. This is the correct tap point for passive listening.
5GNDConnect to common GND.
Consequence of connecting to pin 2 (T1OUT): T1OUT generates −12 V (RS232 mark/idle) whenever T1IN is HIGH. This directly opposes the transmitter on the bus and causes complete communication failure — even though the ESP32 receives nothing it appears to corrupt the line. Always use pin 3 (R1IN) of the female connector.
T1IN pin on the TTL header: may be left floating or tied to GND. It does not affect reception. Do not connect T1OUT (female pin 2) to the RS232 bus regardless of T1IN state.

S3 CNC / GcodeSender

Single pack PACK_S3_CNC. It disables RS232 and enables GRBL+SDCARD+WebSocket+USB_HOST. The GRBL transport is selectable at runtime via the web page selector (session-only): UART is the default at boot, USB Host OTG is activated instantly when chosen. The USB Host always runs; the choice is not persisted (reboot returns to UART).

Transport A: USB Host OTG (runtime selector)

GRBL communicates via USB Host on the native USB port (GPIO19/20) with an OTG adapter. Connects to the GRBL controller's CH340/FTDI/CP2102 USB-UART adapter.

Note: USB Host takes over the native USB port. The USB CDC Serial (Serial Monitor) becomes unavailable. Use the CP2102 UART0 (GPIO43/44) for debug output.
