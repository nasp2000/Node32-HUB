# Node32-HUB

**Node32-HUB** is a modular, multi-protocol firmware framework for ESP32-S3 and ESP32-P4 microcontrollers. It turns a single board into a versatile industrial communication hub, data logger, automation controller, or IoT gateway. Thanks to compile-time feature flags, it can be tailored to fit absolutely any use case.

> **Site:** [nasp2000.github.io/Node32-HUB](https://nasp2000.github.io/Node32-HUB/) — one page per pack: what it does, which board it needs, and the download.

## Architecture

The firmware is organized around a **pack-based module system**, where each "pack" defines a specific device personality by enabling relevant features. Because these modules are independent, a single codebase can generate firmware for completely different use cases, allowing you to mix and match features in endless configurations. 

## Why Node32-HUB?

* **One codebase, many devices** — Build tailored firmware for each board without maintaining separate forks.
* **Optimized footprint** — Only compile the specific features and modules your hardware actually needs.
* **Production-ready & Fail-safe** — Built-in WDT, crash recovery, PSRAM management, and brownout detection.
* **Dual-network redundancy** — Seamless coexistence of Wi-Fi and wired Ethernet for redundant connectivity.
* **Web-based management** — Full configuration, live monitoring, file uploads, and event scheduling directly from any browser.

## Feature Modules

* **Serial:** RS232, parallel port emulation, and dual-RX line sniffing.
* **Networking:** Wi-Fi, Ethernet, mDNS, and NTP.
* **Industrial:** Modbus RTU/TCP/Slave, CAN bus, proximity inputs, digital outputs, and OEE machine tracking with inactivity alerts.
* **Storage:** SD card, LittleFS, PSRAM-backed virtual filesystem, and FTP uploads.
* **Web UI:** Real-time dashboards, configuration portal, file manager, task scheduler, and OTA updates (Wi-Fi + Ethernet).
* **Alerts & Notifications:** SMTP email and webhook-based alerts with storage attachments.
* **Audio:** I2S DAC, MP3 hardware decoding, and internet radio streaming.
* **Camera:** DVP and MIPI CSI-2 camera interface support.
* **CNC & Automation:** USB Host G-code sender for GRBL controllers and USB/IP device sharing.
* **Sensors:** Temperature, humidity, pressure, air quality, load cells, current/voltage, RTD, and sound level monitoring.
* **Display:** LCD / OLED / TFT touch data visualization and status screens.

## Releases

Pre-built firmware is published **in this repository**, one release per pack: the tag names the
pack (`v1.120-cam-s3`, `v1.120-rambox`, …) and every release carries the flashable build folder
plus a separate `_third-party.zip` with the LGPL sources and relinkable objects.

| Pack | Board | What it does | Download |
|---|---|---|---|
| [**Cam-M**](https://nasp2000.github.io/Node32-HUB/packs/cam-m.html) | ESP32-S3 N16R8 | Camera companion (MJPEG stream, snapshots, AVI/motion). | [releases](https://github.com/nasp2000/Node32-HUB/releases?q=cam-s3) |
| [**Rambox32**](https://nasp2000.github.io/Node32-HUB/packs/rambox32.html) | ESP32-S3 N16R8 | Pigeon-racing timing terminal (RS232/Unikon, email alerts, OLED). | [releases](https://github.com/nasp2000/Node32-HUB/releases?q=rambox) |
| [**Harmonica Box**](https://nasp2000.github.io/Node32-HUB/packs/harmonica.html) | ESP32-S3 N16R8 | Internet radio and music streaming (I2S, UPnP, alarm clock). | [releases](https://github.com/nasp2000/Node32-HUB/releases?q=radio) |
| [**GcodeSender**](https://nasp2000.github.io/Node32-HUB/packs/gcodesender.html) | ESP32-P4 | G-code sender (USB Host + heatmap, web UI, SD/PSRAM). | [releases](https://github.com/nasp2000/Node32-HUB/releases?q=p4cnc) |
| **Node32-OEE** | ESP32-S3 N16R8 | Production counting & OEE terminal (8DI8DO, shifts + CSV, A×P×Q, email). | [Node32-OEE](https://github.com/nasp2000/Node32-OEE) (published by hand) |

Each build folder contains `firmware.bin` (OTA-signed), `bootloader.bin`, `partitions.bin`,
`flash_command.txt` and the licence notices; flash over USB (WebFlasher/esptool) or upload
`firmware.bin` at `http://<device-ip>/ota`. Sources for any release are the commit recorded in
its notes ([`RELEASES.md`](RELEASES.md)).
