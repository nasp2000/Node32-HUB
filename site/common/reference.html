Shared pages

Every pack carries the same seven pages, because they are the ones the board itself needs: look at it, move files, read the log, get on the network, lock it, send mail, update it. Everything specific to a pack lives on its own reference page.

Status

Read-only view of what the board is doing: chip model and revision, cores and clock, temperature, heap and PSRAM, storage, network state and uptime. There are no settings here — only Refresh, which re-reads /api/status.

Files

The SD card (and PSRAM, where the pack uses it) as a file explorer: browse folders, upload, rename, delete, create a folder, sort by name or date and filter by typing.

ControlWhat it does
Storage selectorSwitches between SD and PSRAM and reloads the listing at the root of that storage.
FilterHides rows as you type, by file name.
Select / ClearMarks or clears every row; the actions below apply to the selection.
SortReloads the listing ordered by name or by date.
BackGoes up one folder.
DeleteAsks for confirmation, then removes the selected files.
New folder / RenameAsks for a name — rename only accepts a single selected file.

Monitor

The board's log, over the network: the same lines that go out on the serial port, with levels and timestamps. Useful when a pack is not behaving and you have no cable plugged in. The Serial Monitor button on the home page opens the live view; both can be hidden from Access.

Network

Wi-Fi credentials and, on boards that have it, Ethernet. When the board cannot join a network it raises its own access point — NODE32-HUB, password 12345678, address 192.168.4.1 — so you can always reach it. Once joined, most packs answer at <pack>.local over mDNS where the pack enables it.

Email

One SMTP account with TLS, a set of recipients and a test send. Packs that produce events (arrivals, inactivity alerts, shift reports) use this account; without it the events stay on the page.

Updates

/ota takes a firmware.bin and reboots. The image is checked against the built-in RSA-2048 key and the chip magic before it is allowed to boot, so a modified or wrong-board binary is refused — recover with a USB flash. Configuration and stored data survive the update.
